## Conversations

1. **Emoji:** the kit loaded Inter/DejaVu only. RmlUi also has its own FreeType library, with no OT-SVG renderer: merely loading the shipped Twemoji face failed with FreeType 0x9e. The kit now registers the existing classic SVG renderer with that library and loads the already-shipped Twemoji fallback. No new font assets or copied renderer. A pinned/hash-checked application hook is applied to the owned RmlUi build copy. Its existing BGRA glyph path keeps emoji colors independent of text tint. This applies to message bodies, sender names and form inputs.
2. **Markup:** interpolation treated every message as literal text. `slnewui::chatMarkup` now delegates recognition, no-link handling, target URLs and display labels to LLUrlRegistry, using the same untrusted-content policy, 100-match cap and head-scan limit as LLTextBase. It emits only application-generated link spans and escapes all incoming markup, attribute quotes and RmlUi binding delimiters. Label-cache updates invalidate the bounded displayed-message slice through a weak lifetime guard. Clicks call LLUrlAction::clickAction with trusted=false. Covered types: `<nolink>`, HTTP/HTTPS/plain URLs, named/bracket URLs, SLURLs and secondlife app links (agent/group/inventory/other registered types), email/wiki forms handled by the registry; existing `/me` and `/me'` emotes stay intact. Arbitrary HTML and untrusted `<icon>` tags are not promoted to executable markup, matching the registry's trust boundary. No new URL parser or message model.
3. **Layout:** persisted `UINewChatLayout`: 0 IRC (default), 1 grouped sender headers. Live buttons select it. Consecutive messages from the same sender share a header, without merging system/emote/history boundaries. Timestamps remain available. A raw Nearby event with no timestamp is stamped using classic appendTime before publishing to the native model; previously that model read the empty field before classic supplied its timestamp. Profile pictures are deferred: fetching pictures per message is not needed for grouping and would add a separate image lifecycle.
4. **New conversation:** the tab-row + opens a single friends/groups search with at most 32 displayed choices. Enter/click starts the existing avatar/group IM action. With no local match, Enter opens the classic resident picker prefilled with the same query; an explicit Search all residents action does that too. A small picker `searchFor` entry point reuses its existing search flow.

## People

5. **Missing avatars:** the native list always applied NearMeRange (default 162 m). The classic radar ignores that radius when LimitRadarByRange is off. Native Nearby now follows the same policy and LLWorld source, including loaded characters and the region map census; no extra camera/region/chat-range filter. The existing 1024-entry UI bound remains. The shared limit toggle and 20–4096 m range slider stay at the bottom, with the slider disabled when unlimited.
6. **Readouts:** distance to 0.1 m; typing, speaking/voice, friend, muted, normal-chat-range, same region/parcel, sitting, payment-info and personal-note presence flags. Age/seen data and note presence come from the existing radar presentation, retaining its privacy policy and avoiding new property requests. Age/notes also check the live privacy policy before using that cached snapshot; note contents stay in the existing profile Notes view. Nearby presence/name restrictions are honored; an older radar snapshot cannot override a live name-hiding policy. Compact glyphs are bounded to 96 dp; the complete tooltip names every active status and includes age/seen readouts. A shared title-to-viewer-tooltip bridge makes these tooltips functional for all native controls, not just status-bar buttons.

Proposed glyph set (owner can choose a final artwork set): ✎ typing; ◖ speaking; ♪ voice available; ★ friend; ⊘ muted; ≋ normal chat range; ⌂ same region; ▣ same parcel; ↧ sitting; ◆ payment used; ◇ payment on file; ≡ personal notes available. These inherit the kit's text styling. Tooltips use the existing common viewer tooltip service.

7. **Mini-map:** an actual LLNetMap is embedded in the Nearby aperture, with its existing pan/zoom/double-click/context-menu and tooltip behavior. No second map model, offscreen target or readback. Its classic drawing follows the native layer and precedes classic menus/tooltips. Higher native windows clip it using at most 64 stack-stored rectangles; fragmentation overflow suppresses the overlay. It waits for published Rml layout during movement/resizing (normally one frame), and is temporarily omitted while modal/native menu popups are open, avoiding drawing over them. Its object survives tab changes; construction failure suppresses it until the window is reopened. In-world interaction/visual validation remains for the owner.
8. **Resizing:** no disabled resize policy was found. The old 14 dp DOM-only grip was a small/obscurable target; the owner's exact input failure was not reproduced in a viewer. It is now a raised 20 dp grip plus a geometry-based corner fallback, independent of the hovered child. Footer controls reserve that corner. This applies to People, Conversations and Inventory. People defaults to 380×640, minimum 320×460, to accommodate the map and at least one list row; screen bounds still win. Real RmlUi hit/layout tests cover both themes and scales 1.0/1.1/1.5.

## Top bar

9. **Home:** the same gAgent.teleportHome path as the classic navigation bar; no new teleport protocol or bypass.
10. **Favourites:** star dropdown reads the real favourites inventory folder in its stored order. Landmark selection uses the existing teleport path. Add current location opens the classic Add Landmark flow with the favourites destination folder. No inventory writes occur merely by opening the dropdown.
11. **Location:** bubble opens an address field plus existing session teleport and typed-location history suggestions. A small public LLNavigationBar::navigateTo entry point extracts/reuses the existing parser, region resolution and history-update flow. Coordinate-only x/y/z is normalized to the current-region SLURL, then goes through that same path. Location/history display respects location privacy restrictions. Arrow keys skip disabled choices, Enter activates one choice (or submits the typed address), and Escape closes the dropdown before the underlying window.
12. **Left actions:** a Create/Upload button exposes the actual menu-index upload entries (image, sound, animation, model, bulk model, material and bulk, as available/enabled). It reuses menu enable/fee/upload logic. Proposed additional quick actions implemented: Preferences, Search, Snapshot. No replacement command implementations or new upload pipeline.

Nearby double-click previously shared the Friends/Recent IM handler. It now calls the same `SLAvatarActions::zoomIn` as classic radar, including its loaded/coarse-avatar camera behavior and camera constraints. Friends/Recent still double-click to IM. IM remains a row button, a footer action and a context action; double-clicking its dedicated button does not also zoom.

The classic Nearby/radar menu audit added Zoom in, Track, Face towards, Teleport to, transcripts, contact sets, Report, name/profile-link/UUID copying and the three render modes. All call their existing handlers; render modes share an extracted public entry point with the classic radar (including unloaded-avatar persistence/reculling). The bounded menu scrolls within the window instead of extending offscreen.

## Message latency (addendum 14)

The native view checked its model only after a 250 ms metadata timer. An own-send forced a poll immediately, then a Nearby server echo arriving just afterward could wait nearly 250 ms; classic appends on delivery. Both views already read the same model event, so adding a separate optimistic echo would duplicate messages rather than fix the delay.

Nearby now publishes a change event after its line/revision are committed; native Conversations subscribes to it and the existing IM new-message signal. Pending live lines are consumed before the metadata timer, on the next UI capture, for both own and incoming messages. Nearby still uses the same server-delivery semantics as classic; P2P local echo remains the existing LLIMModel path. Scoped connections disconnect on window destruction. Multiple arrivals coalesce into one bounded displayed-slice update.

The existing outgoing initialization queue remains capped at 32, but is checked before the timer too. The view observes the existing session-ID update to carry conversation/queued-send bindings from temporary to canonical IDs. Previously the model erased the old ID before a later native queue poll, which could drop an ad-hoc first message as a missing session. A source-extracted regression checks the actual rebind method preserves payloads and unrelated sessions. Observer registration/disconnect follows the model lifetime.

Unchanged lines retain their formatted rich strings. RmlUi retains data-for row elements and does not replace unchanged data-rml children; no document reload is used for an append. Once the 80-slot live tail rolls, the existing bounded slots receive the shifted data, rather than growing history DOM indefinitely. The CPU event fixture checks synchronous publication/order, ring wrap and disconnect, while the real Rml fixture checks row and rich-child identity across append. Source wiring checks ensure live processing stays before the 250 ms gate. The removed extra delay is source-proven (up to 250 ms), not a measured end-to-end viewer latency claim.
